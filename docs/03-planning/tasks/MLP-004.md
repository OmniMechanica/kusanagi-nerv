# MLP-004 — Durable job controller and safe queue claiming

**Project:** KUSANAGI NERV  
**Priority:** P0  
**Schedule:** Day 04  
**Learning/build timebox:** 3–4 h (estimate, not a deadline)  
**Status:** Planned  
**Dependencies:** [MLP-003](MLP-003.md)

## Objective

Run scheduling in a separate process and claim queued work without duplicate owners.

## Implementation steps

- Create a controller service/entrypoint independent from the FastAPI process.
- Implement safe DB claim/lease using a transaction (`FOR UPDATE SKIP LOCKED` or equivalent).
- Record attempt IDs, stable submission ID and intent before dispatch, lease owner/epoch/expiration and heartbeat or claim timestamps.
- Create a temporary local executor adapter to simulate work while preserving the later Ray interface.
- Test two simultaneous controllers competing for the same pending job.

## Acceptance criteria

- [ ] Two controllers never hold the authoritative active claim for one attempt at the same time.
- [ ] Controller crash/lease expiry allows another process to reconcile and continue.
- [ ] API acknowledgement is independent of controller availability.
- [ ] Attempt identifiers are persisted and traceable.
- [ ] A stale lease holder cannot commit results; fake-executor tests distinguish unknown submit outcomes from confirmed failures without creating another attempt.

## Required evidence

TESTED-CPU: two-controller integration test with transaction barrier; restart test.

## What to study in parallel

Async SQLAlchemy and PostgreSQL transaction docs; backend architecture review.
