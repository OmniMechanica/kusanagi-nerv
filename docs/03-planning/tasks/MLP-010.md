# MLP-010 — Checkpoint storage and real recovery experiment

**Project:** KUSANAGI NERV  
**Priority:** P0  
**Schedule:** Day 10

**Status:** Planned  
**Dependencies:** [MLP-007](MLP-007.md), [MLP-009](MLP-009.md)

## Objective

Prove durable training progress survives worker failure.

## Implementation steps

- Introduce MinIO/S3 object storage for checkpoint and artifact paths.
- Save model, optimizer, last completed epoch, config/seed and metadata; use an atomic publication pattern.
- Kill a worker or trainer process after checkpoint epoch N.
- After observed failure, let the controller create the new attempt within its retry budget. Persist/pass the selected resume checkpoint explicitly; use an attempt-specific output path and restore model/optimizer/epoch, continuing from N+1.
- Observe retries, errors and final artifact status in the durable job ledger.

## Acceptance criteria

- [ ] Checkpoint exists in object storage and can be read by a fresh process.
- [ ] Failure injection causes a new attempt and training resumes after the saved epoch.
- [ ] Experiment records epoch before/after, attempt IDs and checkpoint URI.
- [ ] Runtime worker recovery is explicitly disabled for this experiment; network reconciliation does not increment attempts and the controller's attempt budget is enforced.
- [ ] No misleading claim that restart-from-zero is resume.

## Required evidence

TESTED-CPU: worker-kill script/log + checkpoint and resume proof; describe exact failure boundary.
