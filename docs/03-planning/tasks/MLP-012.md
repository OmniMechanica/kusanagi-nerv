**Project:** KUSANAGI NERV

**Status:** Planned  
**Dependencies:** [MLP-002](MLP-002.md), [MLP-011](MLP-011.md)

## Objective

Improve developer experience with typed self-service access.

## Implementation steps

- Wrap the existing public API with `submit_training`, `get_job`, `cancel_job`, `deploy_model`, `get_model`, `predict`.
- Add timeouts, HTTP error mapping and at least one retry policy for safe GET calls.
- Surface MLP-011's deployment validation, readiness and version metadata through SDK models/errors. Server-side registration and deployment are already P0; this ticket adds only the optional client experience.
- Write SDK contract tests with HTTP mocks and one live local smoke test.

## Acceptance criteria

- [ ] End user does not need Kubernetes commands.
- [ ] SDK errors are typed/useful and retries do not duplicate non-idempotent submissions.
- [ ] Deployment points to an existing, successful model artifact.

## Required evidence

TESTED-CPU: SDK-driven training/deploy/predict smoke test.

## What to study in parallel

FastAPI course API/validation sections and Python HTTP client docs.

## Interview drill

How do you design sync vs async SDKs? How do you handle idempotency on network retries?
