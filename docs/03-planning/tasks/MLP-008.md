# MLP-008 — Reproducible PyTorch training loop

**Project:** KUSANAGI NERV  
**Priority:** P0  
**Schedule:** Day 08  
**Learning/build timebox:** 2–3 h (estimate, not a deadline)  
**Status:** Planned  
**Dependencies:** [MLP-006](MLP-006.md)

## Objective

Create an intentionally small ML workload to exercise platform behavior.

## Implementation steps

- Build a synthetic tabular dataset and a tiny PyTorch MLP/regression model.
- Use deterministic seeds, training/evaluation split and a simple metric.
- Create clean CLI/function entrypoints with typed config and output artifact path.
- Save model state and training metadata without introducing distributed execution yet.
- Write a smoke test that trains quickly on CPU.

## Acceptance criteria

- [ ] Training runs reproducibly on CPU and emits loss/metric and metadata.
- [ ] Model can be loaded for a forward pass; no hidden dataset/cloud dependency.
- [ ] Observed output path can be used by the execution adapter.

## Required evidence

TESTED-CPU: model training script/test with seed, metrics and artifact hash.

## What to study in parallel

MLOps Bootcamp lessons ~16–25; official PyTorch tutorials.

## Interview drill

Which state is required to resume training? Why separate model quality metrics from platform health metrics?
