## Objective

Understand and demonstrate distributed execution independently of the HTTP process.

## Implementation steps

- Run Ray locally on CPU using simple `@ray.remote` tasks.
- Implement a long-lived actor and contrast stateful actor vs stateless task semantics.
- Use explicit resource requests, concurrency limits, pending submissions and backpressure.
- Log task start/end and show work happens outside the API process.
- Write tests/examples showing behavior under N simultaneous submissions.

## Acceptance criteria

- [ ] CPU Ray task and actor run end-to-end with an isolated example.
- [ ] One example demonstrates bounded concurrency and queue/pressure behavior.
- [ ] You can explain the object store, remote refs and failure boundaries.
- [ ] No assumptions about GPU availability.

## Required evidence

TESTED-CPU: reproducible Ray script/test and observed concurrency logs.

## What to study in parallel

Official Ray Core tasks and actors tutorials.

## Interview drill

Ray task vs actor? When would a Python thread/process pool be enough? How does Ray allocate requested resources?
