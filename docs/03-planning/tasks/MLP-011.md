# MLP-011 — Ray Serve inference and self-service model deployment

**Project:** KUSANAGI NERV

## Objective

Serve a persisted model without invoking training from the inference request.

## Implementation steps

- Finalize a successful training job with an idempotently registered model record; expose its ID/version/artifact in job status.
- Implement tenant-scoped deploy and model GET routes from the [API contract](../../01-product/api-contracts.md#model-registration-deployment-and-prediction-mlp-011), including deployment state/error and successful-artifact checks.
- Load the completed model artifact from object storage into a Ray Serve deployment with a stable deployment identity; reconcile desired state after controller restart.
- Implement simple predict contract with input validation and model version in response.
- Expose predict through the public API with validation, tenant context and not-ready/unavailable errors. A direct Ray Serve URL is supplementary operational access, not the acceptance path.
- Test model restart/redeployment and concurrent requests.
- Add p95 latency and failure status as observability discussion points.

## Acceptance criteria

- [ ] `predict` returns deterministic output from an artifact stored outside the worker.
- [ ] Model version is visible and request validation handles malformed payloads.
- [ ] Serving does not trigger retraining and works after a service restart.
- [ ] Basic inference integration test passes.
- [ ] A caller can obtain `result_model_id`, deploy it, poll readiness and predict using only the public HTTP API, without the optional SDK or manual Ray commands.
- [ ] Repeated registration/deploy and controller restart preserve the model/version and desired deployment identity; incomplete artifacts and unauthorized access are rejected.

## Required evidence
