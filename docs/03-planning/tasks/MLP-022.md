# MLP-022 — Actual GPU train run and telemetry

**Project:** KUSANAGI NERV  
**Priority:** P2  
**Schedule:** Stretch (unscheduled)  
**Learning/build timebox:** 3–6 h (estimate, not a deadline)  
**Status:** Planned  
**Dependencies:** [MLP-009](MLP-009.md), [MLP-016](MLP-016.md)

## Objective

Validate GPU capacity and usage empirically on real NVIDIA hardware.

## Implementation steps

- Provision a controlled-budget GPU environment with driver and proper runtime.
- Run the same tiny Ray Train workload on CPU and GPU, holding parameters comparable.
- Record physical GPU, memory usage, utilization and elapsed time using NVIDIA tools.
- Shut down resources and record estimated cloud spend.

## Acceptance criteria

- [ ] Real `nvidia-smi`/DCGM trace and GPU execution logs exist.
- [ ] Comparison notes state hardware, batch size and limits; no false performance generalizations.

## Required evidence

TESTED-GPU: run logs, device/runtime versions and cost/time notes.

## What to study in parallel

NVIDIA GPU Operator, Ray Train and GPU observability docs.

## Interview drill

Why might GPU run slower for tiny workloads? How do utilization and allocation differ?

## Definition of Done

Pass applicable checks in [Definition of Done](../../06-engineering/definition-of-done.md); log result and evidence in [progress](../progress.md). Do not call design-only work a successful hardware run.
