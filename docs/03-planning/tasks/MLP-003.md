## Objective

Make job records survive process restarts and define a durable persistence contract.

## Implementation steps

- Introduce SQLAlchemy asyncio, PostgreSQL connection/session management and one Alembic migration.
- Model `jobs` with tenant (test placeholder initially), spec, status/version, timestamps, idempotency hash.
- Model `job_attempts` early or document its next-step migration; preserve separation of logical job and attempts.
- Replace in-memory repository via dependency injection, using transactional writes.
- Write DB integration tests using a real PostgreSQL instance or disposable test DB.

## Acceptance criteria

- [x] Job remains available after API restart, including a real process killed after acceptance.
- [x] A migration reliably creates schema; no unconditional destructive startup reset.
- [x] Concurrent state updates cannot silently overwrite one another: conditional tenant/ID/status/version updates are tested with competing writers and a stale-version retry cycle.
- [x] Database errors surface as controlled `503` failures; tests pass.

## Implementation boundaries

`0001_job_ledger` creates the logical job ledger, indexes and constraints. Creation commits queue admission in one transaction. Each operation owns its session; the app lifespan disposes the connection pool. The API requires a PostgreSQL URL, while fast tests explicitly inject memory.

The stored payload hash and nullable idempotency-key column prepare for MLP-005; they do not implement deduplication. The [next migration](../../02-architecture/data-model.md#next-migration-mlp-004) adds attempts and lease/submission authority before any dispatch. Version-guarded writes alone do not establish contextual cancellation safety. Production tenancy, a controller and model execution remain later tasks.
