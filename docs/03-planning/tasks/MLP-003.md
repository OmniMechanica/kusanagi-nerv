## Objective

Make job records survive process restarts and define a durable persistence contract.

## Implementation steps

- Introduce SQLAlchemy asyncio, PostgreSQL connection/session management and one Alembic migration.
- Model `jobs` with tenant (test placeholder initially), spec, status/version, timestamps, idempotency hash.
- Model `job_attempts` early or document its next-step migration; preserve separation of logical job and attempts.
- Replace in-memory repository via dependency injection, using transactional writes.
- Write DB integration tests using a real PostgreSQL instance or disposable test DB.

## Acceptance criteria

- [ ] Job remains available after API restart.
- [ ] A migration reliably creates schema; no unconditional destructive startup reset.
- [ ] Concurrent state updates cannot silently overwrite one another (guard/version proposed and tested).
- [ ] Database errors surface as controlled failures; tests pass.

## Required evidence
