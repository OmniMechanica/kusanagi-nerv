## Objective

Compare DAG workflow orchestration and Ray runtime through one real workflow.

## Implementation steps

- Define a tiny workflow with preprocessing, training and evaluation stages.
- Add caching/retry/materialized output to demonstrate Flyte-specific semantics.
- Compare with Ray Train+controller using ADR dimensions.
- Record setup/operations tradeoffs and when to combine both tools.

## Acceptance criteria

- [ ] Workflow runs or is clearly DESIGN-ONLY with named blocker.
- [ ] Can explain scheduling granularity, retry semantics, caching and lineage tradeoffs.
